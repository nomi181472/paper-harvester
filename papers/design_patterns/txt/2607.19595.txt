A BSTRACT
Large language model (LLM) agents are vulnerable to security risks, such as prompt
injection attacks from untrusted context that manipulate downstream reasoning and
tool use. Existing secure-by-design approaches mitigate this risk by separating
untrusted observations from privileged execution and careful control of information
flow, but often degrade utility and require extensive task-specific engineering. We
thus propose Twin Agent, a general privilege separation design pattern inspired by
residual coding in the agent context. Twin Agent consists of two nearly symmetric
agents: an Explore Agent that inspects untrusted information and a Safe Agent
that executes privileged actions. The Explore Agent is conditioned on the Safe
Agent’s current context and communicates only compact hints to the Safe Agent
about the next action to take. This design reduces the information needed to
preserve task utility and thus achieves a better security–utility tradeoff, which we
empirically verify by measuring how utility and attack success change as the length
of hints varies. We evaluate Twin Agent on long-horizon software engineering
tasks with SWE-bench Lite and on heterogeneous multi-tool interaction tasks
with AgentDojo and DecodingTrust-Agent. Across both benchmarks, Twin Agent
preserves high task utility while preventing prompt injection attacks, outperforming
both undefended agents and privilege separation baselines.

I NTRODUCTION

Large language model (LLM) agents increasingly operate in open environments where they must
process untrusted information while retaining the ability to perform privileged actions, such as code
execution, file-system access, web browsing, or API calls (Yao et al., 2023; Anthropic, 2024; OpenAI,
2025; Anthropic, 2025). This creates a fundamental security challenge for agentic systems: untrusted
inputs can manipulate downstream reasoning and tool use through prompt injection attacks, leading
to harmful or unintended actions (Willison, 2022; Perez & Ribeiro, 2022; Greshake et al., 2023; Liu
et al., 2024).
Secure-by-design strategies address this challenge by separating untrusted observations from privileged execution. A typical Dual LLM design pattern (Willison, 2023) leverages privilege separation
to assign different trust levels to different components, allowing one component to observe untrusted
information while another retains authority over privileged actions (Provos et al., 2003; Debenedetti
et al., 2025; Beurer-Kellner et al., 2025). By explicitly restricting information flow across trust
boundaries, these approaches provide a principled path toward secure agent design.
Existing secure-by-design methods, such as CaMeL (Debenedetti et al., 2025), often adopt plan-first
patterns that perform privileged planning before interacting with untrusted environments. However,
many realistic agentic tasks require iterative exploration, environment feedback, and dynamically
changing agent trajectories (Yao et al., 2023; Yang et al., 2024; Anthropic, 2024). For example,
software engineering agents must repeatedly inspect repository states, execute commands, observe

systems often suffer from severe utility degradation and require manually designed workflows, rigid
communication interfaces, or task-specific security policies, making them difficult to adapt across
heterogeneous agentic tasks.
We argue that secure agent design is better understood as a compressed information flow problem
for communication among agents. Attacks such as prompt injection require the transmission of
sufficient attack-carrying information to override the intended behavior of the privileged agent.
Empirically, we observe that attacking the latest, strongest models requires long injections, so the
attacker needs to send a lot of information to succeed. In contrast, preserving task utility often
requires only the information necessary to support the agent’s next useful action. As illustrated in
the left panel in Figure 1, a robust yet helpful defense should therefore maximize the separation
between two quantities: the amount of information needed to preserve utility-oriented actions and
the amount of information needed to induce behavioral override. This perspective unifies several
existing defense paradigms. Guardrails, monitors, and model-based defenses increase the amount of
information required for a successful override by reinforcing desired behavior or filtering suspicious
instructions (Chen et al., 2024; Piet et al., 2024; Chen et al., 2025a; Jacob et al., 2025; Li et al., 2025;
Chen et al., 2025b). In contrast, privilege separation architectures reduce the amount of information
allowed to cross the trust boundary (Willison, 2023; Debenedetti et al., 2025; Beurer-Kellner et al.,
2025; Costa et al., 2025; Jacob et al., 2026).
Under this principle, and inspired by residual coding (Lu et al., 2019), we propose Twin Agent, a
privilege-separated agent design that aims to preserve utility while controlling information flow from
untrusted sources. Twin Agent consists of two nearly symmetric agents: an Explore Agent and a Safe
Agent. The Explore Agent can observe untrusted information, but cannot execute privileged actions.
The Safe Agent can execute privileged tools, but cannot directly observe untrusted information.
Instead of passing unconstrained input to the Safe Agent, Twin Agent uses a restricted hint channel:
conditioned on the Safe Agent’s limited task state, the Explore Agent communicates only the taskrelevant residual information needed for the Safe Agent’s next decision. Figure 2 compares Twin
Agent with alternative agent designs. The key idea is that secure communication is more effective
when it is differential rather than absolute. Because the Explore Agent is conditioned on the Safe
Agent’s current context state, most of the information is already shared. At each step, the Safe Agent
does not need a complete sanitized summary of the untrusted context; it only needs the minimum
context required to decide the next privileged action. Twin Agent therefore communicates compact
residual information rather than retransmitting complete observations or another agent’s context.
This design has two benefits. First, it improves the security–utility tradeoff, making it controllable
and measurable. It provides a tunable parameter (the bound on hint length) for controlling this

Second, Twin Agent is a drop-in replacement for the ReAct pattern and requires little task-specific
workflow engineering. Rather than redesigning a new secure workflow for each different domain,
Twin Agent is a universal defense that preserves the original agentic interaction pattern and inserts a
lightweight residual communication layer between untrusted observations and privileged execution.
This facilitates the secure adaptation of existing utility-oriented agents with small architectural
modifications, and it makes Twin Agent particularly suitable for long-horizon and adaptive tasks
where pre-specified plans or rigid-typed interfaces are difficult to maintain (Debenedetti et al., 2025;
Costa et al., 2025; Jacob et al., 2026). Third, Twin Agent partially disentangles utility preservation
from security enforcement. Under a fixed communication budget, utility is primarily determined by
the Explore Agent’s ability to extract task-relevant information, while security is primarily determined
by the isolation and security controls of the Safe Agent.
We evaluate the Twin Agent design on two complementary classes of agentic systems. First, we
evaluate on SWE-bench, representing long-horizon software engineering tasks that require adaptive
exploration and iterative debugging (Jimenez et al., 2024; Yang et al., 2024). This setting is especially
challenging for existing secure-by-design systems. Second, we implement tool-using agents for
AgentDojo (Debenedetti et al., 2024) and DecodingTrust-Agent (Chen et al., 2026), which represent
heterogeneous multi-tool interaction environments with dynamically changing tool outputs and
interaction states. Across all benchmarks, Twin Agent shows high utility and resistance to prompt
injection attacks.
Our contributions are summarized as follows:
• We propose Twin Agent, an agentic defense based on privilege separation that preserves
utility, features strong robustness against prompt injection, and requires limited task-specific
redesign.
• We formulate secure agent design as a compressed information flow problem. This perspective motivates a principled relaxation of strict privilege separation, where the security–utility
tradeoff can be controlled by limiting the amount of information allowed to cross the trust
boundary.
• We evaluate Twin Agent on both long-horizon adaptive reasoning tasks and heterogeneous
multi-tool interaction benchmarks. Experiments show that Twin Agent achieves high task
utility while preventing prompt injection attacks, outperforming both undefended agents
and strongly isolated privilege separation baselines.

R ELATED W ORK

Prompt injections attacks. Prompt injection attacks embed malicious instructions directly in
user inputs or indirectly in external content, causing LLMs to confuse untrusted data with trusted
instructions and follow attacker-specified objectives (Perez & Ribeiro, 2022; Greshake et al., 2023;
Liu et al., 2024). For LLM agents, such attacks can manipulate multi-step reasoning and induce
unauthorized or harmful tool actions (Debenedetti et al., 2024; Zhan et al., 2024).
Model-Based defenses. Many existing prompt injection defenses focus on improving the robustness
of the underlying model itself. Detector-based approaches train classifiers to identify malicious inputs
and act as filters before the downstream agent or model (ProtectAI.com, 2023; AI, 2024; Wan et al.,
2024; Jacob et al., 2025; Li et al., 2025; Meta, 2025). Fine-tuning approaches directly train foundation
models on prompt injection attacks to improve robustness against adversarial instructions (Chen et al.,
2024; Piet et al., 2024; Chen et al., 2025a;b). These methods can improve robustness, but they remain
vulnerable to adaptive attacks. Successfully attacking the latest, strongest models seems to require
fairly long malicious prompt injections, and we take advantage of this in our design.
Secure-by-design agent architectures. More recent work addresses prompt injection at the architectural level with privilege separation (Provos et al., 2003; Willison, 2023; Debenedetti et al.,
2025; Beurer-Kellner et al., 2025; Costa et al., 2025; Jacob et al., 2026). These approaches separate processing of untrusted information from privileged execution, typically using the Dual LLM
pattern (Willison, 2023) or multi-stage workflows. Existing methods instantiate this idea through
plan-first execution, structured communication interfaces, restricted data types, or constrained information flow between trusted and untrusted contexts (Debenedetti et al., 2025; Beurer-Kellner et al.,
2025; Costa et al., 2025; Jacob et al., 2026). These approaches significantly improve security, but
often rely on heavily engineered workflows, rigid communication protocols, or task-specific security
policies. This can lead to significant utility degradation and thus is not practical for all tasks.

We first formalize the threat model and review existing secure-by-design agent patterns and their
limitations. We then introduce Twin Agent, in which an Explore Agent sends bounded hints derived
from untrusted context to a Safe Agent that performs privileged actions.

A PPLYING T WIN AGENT TO E XISTING AGENT S YSTEMS

Twin Agent is designed as a general-purpose privilege separation framework that preserves the reasoning dynamics of existing undefended agents with minimal task-specific redesign. To demonstrate
this property, we instantiate Twin Agent on substantially different agent systems, including SWEagent for SWE-bench (Jimenez et al., 2024; Yang et al., 2024) and tool-using agents for AgentDojo
(Debenedetti et al., 2024) and DecodingTrust-Agent (Chen et al., 2026). These systems differ in
reasoning styles, execution environments, tool interfaces, and threat surfaces, enabling us to evaluate
the generality of Twin Agent across heterogeneous agent architectures.
Across all instantiations, the core adaptation pattern remains consistent: (1) privileged actions are
separated from untrusted information processing; (2) an Explore Agent is introduced to access the
full untrusted context; and (3) the Explore Agent communicates compact hints to the Safe Agent, to
try to keep the trajectory close to that of the original undefended agent.
4.1

SWE- AGENT FOR SWE- BENCH

A SWE-bench (Jimenez et al., 2024) agent autonomously fixes GitHub issues by generating patches
to real-world code repositories. User-submitted GitHub issues can be submitted by untrusted users,
and hence could contain prompt injection attacks (Jacob et al., 2026). Therefore, a malicious issue
could manipulate a naive bugfixing agent to make malicious changes to the repository, such as adding
a backdoor to the code. To evaluate this risk, we create SWE-bench-injected, a modification of
SWE-bench where issue descriptions are injected with attacks that instruct the agent to perform an
attacker-specified action (i.e., writing to a file, deleting a file).
The baseline SWE-agent is a ReAct-style software engineering agent designed for repository-level
debugging and issue resolution (Yao et al., 2023; Yang et al., 2024). The original agent is provided
with detailed instructions on how to read issue descriptions, inspect repository state, generate
debugging hypotheses, and execute bash commands while observing the resulting execution output.
We apply the Twin Agent methodology to this baseline agent to secure it against prompt injection.
See the system prompts of different agents in Section D. The Explore Agent can read the full issue
description and repository contents and optionally pass a hint to the Safe Agent. It also outputs a
virtual bash command that would not be executed. The Safe Agent can read and write the repository
and create a patch, but cannot read the issue description (which comes from an untrusted source).
In each reasoning step, the Explore Agent optionally provides a compact hint to the Safe Agent,
conditioned on the Safe Agent’s trajectory so far, to suggest how the Safe Agent can make progress.

4.2

T OOL -U SE AGENT FOR AGENT D OJO AND D ECODING T RUST- AGENT

We also instantiate Twin Agent on AgentDojo (Debenedetti et al., 2024) and DecodingTrustagent (Chen et al., 2026), which evaluate LLM agents across diverse tool-use environments and
multi-tool interaction settings. In both benchmarks, tool outputs are untrusted, while the system
messages and the user’s instructions are trusted. The original undefended agent is designed to fulfill
users’ requests by iteratively calling various tools and observing their output, creating a large attack
surface for prompt injection.
We apply Twin Agent to the baseline undefended agent. The Explore Agent can observe tool outputs
and provide hints, while the Safe Agent performs privileged actions based only on trusted context
and the hint messages.
4.3

W HY IS IT SECURE ?

The security of Twin Agent is based on a key assumption: it is hard to mount successful promptinjection attacks on frontier models, using short injections. We have observed that the security of
the latest models is improving, and they can still be attacked, but the attacks tend to require long
injections that eventually convince the model to follow the attacker instructions. Therefore, we limit
the length of hints (and truncate or block hints that are longer than the limit), to prevent them from
being used as an avenue of attack.
To add security, we add an additional guardrail: we apply an off-the-shelf prompt injection detector to
each hint, and block the hint if it is detected to contain a prompt injection. (Our detector uses a generic
prompt found in Section A.) Therefore, we rely on the following assumption: it is hard to find a short
injection that will simultaneously evade detection by our detector and also successfully attack the
Safe Agent’s model. Our experiments with strong adaptive attacks appear to support this assumption.
Because the hint is the only input to the Safe Agent that can be influenced by untrusted content, it is
the only risk for prompt injection; by eliminating that risk, Twin Agent is secure-by-design against
prompt injection.

5.1

E XPERIMENTAL S ETUP

Benchmarks. For SWE-bench (Jimenez et al., 2024), we filter 232 debugging instances out of 300
from SWE-bench Lite. To test robustness, we use two attack payloads: (1) instruct the agent to write
a secret code to a new file, and (2) delete an existing file in the repository. We randomly sample from
these payloads and inject them into the instance issue description. We refer to this benchmark as
SWE-bench-injected.
For AgentDojo (Debenedetti et al., 2024), we use all four environments: workspace, slack, travel,
and banking. We adopt the default important_instructions attack for our experiments, in which
malicious instructions are injected into tool outputs.
For DecodingTrust-Agent (Chen et al., 2026), we focus on the CRM and Finance suites, as they
exhibit the highest prompt injection success rates through environment injection. From these suites,
we construct a subset of 60 task instances, each paired with a corresponding prompt injection attack
embedded in the tool responses.

Evaluation Metrics.

We evaluate both utility and security.

• Utility: the percentage of tasks completed successfully according to the benchmark-specific
evaluation protocol.
• Attack Success Rate (ASR): the percentage of attacked tasks in which the agent follows

For CaMeL, we reduce the privileged agent retry budget from max_attempts=10 to max_attempts=3
for computational efficiency. All other hyperparameters are kept at their default settings. This budget
reduction drops the utility from the ∼ 35% reported in the original paper to our evaluated 30.9%.

M AIN R ESULTS ACROSS B ENCHMARKS

Table 1 reports the main results on all benchmarks. Table 2 reports the suite-wise results of the four

In general, we find that unrestricted agents achieve strong clean-task performance but remain highly

Twin Agent achieves a substantially improved security–utility tradeoff across all evaluated settings.
Compared to unrestricted agents, Twin Agent significantly reduces ASR, achieving almost 0.0%
while preserving much of the original task performance. The utility of Twin Agent is slightly higher
than that of the baseline agent, suggesting that a cleaner, more compact context may carry utility
benefits as well.

among 57 instances), Safe Agent finally executes the malicious action. See Section F for a failure
example. This appears to be a random failure due to the non-determinism inherent in language
models: when we rerun these 11 instances 5 times, none ultimately execute the malicious action (i.e.,
0 successful instances out of 55), suggesting that attack success is stochastic under the evaluated
decoding setup. Nevertheless, any nonzero success constitutes a security failure, while the ASR can
be further reduced by improving the security guardrail or by adopting a multi-run voting mechanism.

C ONCLUSION

Prompt injection remains a significant barrier to the real-world deployment of agentic systems. We
propose Twin Agent, a privilege-separated architecture that defends against prompt injection by
adopting insights from compression. Instead of exposing a privileged agent to raw untrusted context
or forcing a rigid plan-first workflow, Twin Agent separates exploration from execution and allows the
Explore Agent to send only compact hints to the Safe Agent. Experiments on SWE-bench-injected,
AgentDojo, and DecodingTrust-Agent show that this design preserves much of the original agent’s
utility while substantially reducing attack success rates, outperforming both undefended agents and
prior methods for system-level defense against prompt injection. Our analysis further shows that the
security–utility tradeoff can be empirically controlled through the hint budget, suggesting that our
approach is practical for building adaptive yet secure LLM agents.
Limitations. Despite these results, Twin Agent still has several limitations. We have evaluated on
only a few application domains; more work is needed to evaluate it on other tasks. Also, Twin Agent
empirically appears secure, but it provides no formal guarantees, so it is conceivable that stronger
attacks could defeat our design.

B

T RAJECTORY P RESERVATION A NALYSIS

A key design goal of Twin Agent is to preserve the reasoning dynamics of the original utility-oriented
agent while providing privilege separation. To evaluate whether Twin Agent preserves the original
reasoning trajectory, we compare the trajectories produced by the defended agent with the trajectories
of the unrestricted original agent on SWE-bench. We also consider a no-hint Safe Agent baseline, in
which the Safe Agent cannot observe the untrusted region and receives no residual hints from the
Explore Agent.
We assess trajectory similarity at the semantic level using an LLM judge. For each task instance, we
split the candidate trajectory into 10 checkpoints. The LLM judge outputs a trajectory deviation score
from 0.0 to 1.0, where 0.0 indicates a trajectory nearly identical to the undefended agent, and 1.0
indicates a trajectory completely different from the undefended agent.
Figure A2 visualizes some examples. Twin Agent achieves a substantially lower trajectory deviation
from the undefended agent than the no-hint baseline, indicating that the hint messages help preserve
the original dynamics.
